# Design: timing out unanswered questions

This plugin updates only OpenCode V2's built-in `question` tool. Its Effect-native `Plugin.define` setup uses `ctx.tool.transform` to wrap the tool's existing executor with `Effect.timeoutOption`. The original executor runs in the same request Effect context, so normal answers and ordinary errors retain their original behavior. Options are validated at setup: `timeoutMs` defaults to five minutes, `allowBlockers` to `false`, and `continueOnTimeout` to `true`.

That request context matters to the TUI: a previous Promise-based adapter lost the ambient request location on `form.created`. The TUI could show “Asked 1 question” without displaying the choices. Composing the timeout inside the Effect instead preserves the location needed to deliver the form to the client.

When `allowBlockers` is enabled, the transform extends the native Effect input schema with an optional `blocker` boolean on each question and describes it to the model. It reuses the host's optional `multiple` boolean schema: constructing a primitive from the plugin's separate Effect copy can turn decoded values into foreign parser sentinels. Schema checks and annotations are preserved without mutating the original schema. If any question declares `blocker: true`, the entire form uses the original executor without a timeout. The plugin strips its own field before passing questions to that executor. Omitted or false flags keep the deadline; with `allowBlockers` disabled, the schema is unchanged and declarations cannot bypass the deadline.

If the deadline expires, the waiting question Effect is interrupted and its form is canceled. The returned result contains one empty answer array per question, `metadata.timedOut: true`, and agent-visible text stating that the user may be away and did **not** approve anything. By default, that text tells the agent to continue with its recommended option for non-blocking choices, choose a safe default if no recommendation was given, and state its assumptions. `continueOnTimeout: false` restores the previous generic timeout guidance. The output never fabricates a user answer.

An answer after cancellation cannot retroactively complete the form. A timely answer passes through unchanged; explicit dismissal and session interruption are not reclassified as timeouts, including on the indefinite blocker path.

Permission prompts are separate from questions and are not wrapped. Required answers and explicit approvals must still come from the user. The continuation option supplies model guidance rather than forcing another session prompt or overriding the model's decisions.
